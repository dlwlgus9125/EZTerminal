# EZTerminal 2.0.0 개발 후보

Identity: remote protocol v17, Android versionCode 78. 공개 배포하지 않은 로컬 개발 후보이며,
실제 구현·검증 상태는 [구현 진행 기록](../ezterminal-v2-implementation.md)이 소유한다.

- 프로젝트의 요구사항·기능·정보 구조·흐름·시안을 연결하고 초안·확정본·변경 이력을 보존한다.
- 같은 대화를 말풍선과 CLI 스킨으로 표시한다. 기존 PTY 터미널은 별도 실행 기능으로 유지한다.
- 역할별 프로필·모델과 확정 입력으로 작업을 준비하고, 명시적으로 시작한다.
  분업·후보 비교·독립 검토와 별도 Git 작업 사본의 로컬 통합을 제공한다.
- 이미지·폰트가 포함된 시안 이동, 인증 정보를 제외한 프로젝트 기록 백업·복원과 수동 정리를 제공한다.
- Android는 PC의 실행 권위를 사용하며 기기 초안과 미확정 요청을 보존한다.
- R7.1 대화 화면은 입력창 설정, 접을 수 있는 실행 기록, 대기열 편집과 변경 패치 인용을 제공한다.
  프로젝트별 새 대화·새 터미널과 독립 UI 작업 공간, 분할·집중 보기를 연결한다.
  두 스킨과 기본·사용자 테마는 같은 대화 상태를 유지한다.

## 처음 사용하는 순서

1. **프로젝트**에서 작업할 폴더를 등록하거나 기존 프로젝트를 연다.
2. **기획**에서 요구사항·기능·정보 구조·사용 흐름을 작성하고, **설계**에서 연결된 화면과 상태를 편집한다.
3. AI 제안을 사용하는 경우 변경 내용을 검토하고 명시적으로 적용한다. 현재 기획 제안 생성은 Claude SDK를 지원하며 일반 Codex 대화·실행은 별도로 유지된다.
4. **작업**에서 작업 의존성·역할별 프로필·모델을 정하고 확정한 입력으로 실행을 준비한다. 시작을 눌러야 실행된다.
5. **검토**에서 결과 diff·검증 근거·독립 검토를 확인하고 별도 Git 통합 후보를 검증한다.
6. 대화는 말풍선/CLI 스킨을 선택한다. 실제 쉘이 필요하면 **터미널**, 기존 보조 기능은 **도구**를 연다.

Android에서는 같은 PC에 연결한 뒤 프로젝트를 연다. 연결이 끊기면 기기 초안을 유지하며,
재연결만으로 자동 저장·재전송하지 않는다. 저장 결과가 불명확하면 기존 요청의 결과를 먼저 대조한다.

R7 로컬 설치 후보의 목적지는 `artifacts/r7-release-2026-10-14/`다.
Windows 설치 파일은 `EZTerminal-Setup-2.0.0-r7.exe`, Android 패키지는
`EZTerminal-Android-2.0.0-vc77-r7.apk`로 식별한다. 실제 빌드·서명·설치 검사 결과는
[R7.1 구현 기록](../ux/reviews/2026-10-14-conversation-r7-implementation.md)과 산출물 manifest가 소유한다.
기존 설치판 업데이트·물리 기기의 IME·공개 출시 검증 완료를 뜻하지 않는다.
기존 버전의 릴리스 문서와 공개 산출물은 변경하지 않는다.

## 이전 버전 앱과 함께 쓸 때 (원격 프로토콜 v17)

소프로젝트 흐름에 단계별 노력·실행 설정·반복 일정·실행 중 단계 결합이 생겨 원격 프로토콜이 v17이 되었다.
이전 Android 앱(v16 이하)은 흐름 데이터를 엄격하게 읽으므로 모르는 칸이 하나만 있어도 그 프로젝트를 읽지 못한다.
아래는 2.0의 목표 계약이다. 개발 중인 지금은 프로토콜 v17·축소 보기·쓰기 보호·초안 분리가 먼저 들어갔고,
새 칸 자체와 결합값 표시·새 버튼의 버전 제한은 각 기능 단계에서 함께 들어간다.

- **새 PC + 이전 Android 앱**: PC가 새 칸을 뺀 흐름을 보낸다. 대화·흐름 보기·승인·실행 제어는 그대로 되고,
  새 칸을 지우거나 바꾸게 되는 흐름 편집(단계 편집·되돌리기)만 "Android 앱 업데이트 필요"로 거절한다.
  이전 앱에도 실행 중 바뀐 단계 설정은 실제로 쓰인 값으로 보인다(새 칸만 빠진다).
- **새 Android 앱 + 이전 PC**: v16 이하로 연결하고 새 기능 버튼을 숨긴다. 새 칸이 담긴 기기 초안은 이전 PC로
  자동 재전송하지 않는다. "다시 실행"(`run.launch`)과 실행 설정 저장은 v17 PC에만 보내고, 이전 PC에서는 준비 + 시작으로 실행한다.
- **한 흐름에 끝나지 않은 실행은 하나**: 새 PC는 같은 소프로젝트에 시작된 뒤 끝나지 않은 실행(일시정지·확인 중 포함)이 있으면
  새 실행 시작을 거절한다. 이전 Android 앱의 시작도 같은 규칙을 따르고, 실행 준비만은 그대로 된다.
- **Android 앱을 이전 버전으로 되돌릴 때**: 새 앱은 흐름 초안을 새 저장 키에 쓰므로 이전 앱은 자기 초안을 그대로 읽는다.
- **데스크톱을 이전 버전으로 되돌릴 때**: 새 칸(실행 설정·"다시 실행" 요청 기록 포함)이 있는 소프로젝트 파일(`workflows.json`)은
  이전 버전에서 '손상'으로 보이며 원본은 그대로 보존된다. 반복 일정은 멈춘다. 진행 중인 실행은 먼저 끝내거나 취소한다. 새 버전에서 만든
  프로젝트 보관본은 새 버전에서만 복원한다. 데스크톱 흐름 초안도 새 파일에 쓰므로 이전 버전은 자기 초안을 읽는다.

## 반복 일정

소프로젝트 흐름을 매일 또는 매주 정한 요일·시각에 저장된 설정으로 다시 실행한다(실행 막대의 `반복`).
PC 앱이 로그인할 때 시작하고 창을 닫아도 계속 실행되도록 켜져 있을 때만 돈다. 예정 시각에서 30분 안에 시작하지 못한 회차는
`놓침`으로 기록하고 실행하지 않는다. 한 흐름은 현지 날짜마다 한 번만 반복 실행되며, 앞 실행이 끝나지 않았으면 그 회차를 건너뛴다.
회차 기록과 "이 PC에서 반복을 켰다"는 기록은 PC의 사용자 데이터 폴더 `workflow-repeat-v1.json`에 있다.
흐름 파일은 프로젝트 폴더에 있으므로, 저장소와 함께 들어오거나 이 PC를 거치지 않고 바뀐 흐름(단계·지시·검토 AI 등)의 반복은
이 PC에서 사람이 다시 켜기 전에는 돌지 않는다. 이 PC의 앱에서 한 편집은 그대로 반복에 이어진다.
기록 파일을 읽을 수 없으면 원본을 그대로 두고 모든 반복을 멈춘다(파일을 옮기거나 지운 뒤 반복을 다시 켜면 돈다).
복사하거나 보관본에서 복원한 흐름은 반복이 꺼진 채로 시작한다.

## 작업 폴더 정리

흐름을 실행할 때마다 단계마다 Git 작업 폴더(worktree)가 생긴다. 흐름 화면 ⋯의 `작업 폴더 정리…`(PC 앱)가 흐름마다 최근 3개 실행을
남기고, 그보다 오래된 끝난 실행의 폴더 중 사람이 남긴 것이 없는 폴더만 지운다. Git이 보관하지 않는 파일(무시된 파일 포함)이나
넣지 않은 변경이 있으면 그 폴더는 남기고 이유를 보인다. 정리한 실행의 결과·변경·단계 대화는 그대로 볼 수 있다(결과는 프로젝트
저장소의 결과 기록에서 읽는다). 정리 기록은 PC의 사용자 데이터 폴더 `run-retention-v1.json`에 있다.
