# EZTerminal 1.0.10

## 모바일 CLI 에이전트 세션 정지 근본 수정

- 모바일에서 시작한 대량 출력 실행(CLI 에이전트)이 재접속·재개나 5분 포트
  임대 만료 뒤 일정 출력량(1MiB) 시점에 휴대폰과 데스크톱 양쪽에서 동시에
  멈추던 문제를 근본 원인에서 수정했습니다.
- 원인은 실행의 primary 포트가 사라진 뒤 흐름제어 창을 되돌릴 경로가 없어
  PTY가 영구 일시정지되는 구조 결함이었습니다. 이제 mirror가 실행을 유지하는
  동안 primary 포트가 사라지면 해당 창을 해제해 모든 화면의 출력이 계속
  흐르고, ESC 등 입력의 화면 반응도 유지됩니다.
- 1.0.9의 임대 만료 후 제어권 복원은 그대로 유지됩니다. 이번 수정은 제어권이
  아니라 출력 흐름의 정지를 다룹니다.

## 원격 연결 안정화 3종

- 원격 브리지를 껐다 켜도 실행을 시작한 모바일 설치의 제어권 신원이
  유지됩니다. 이전에는 브리지 재시작 후 재개하면 보기 전용으로 강등됐습니다.
- 재개 시 replay 재설정에서 mirror 자동응답 입력 게이트를 함께 재설정해,
  유실된 xterm write 콜백이 해당 화면의 키보드 입력을 영구히 삼키지
  못하게 했습니다.
- 인증 후 45초 이상 서버 메시지가 없으면 기존 `list-runs` 왕복으로 연결
  생존을 확인하고, 응답이 없으면 소켓을 닫아 자동 재접속·재개 경로로
  복구합니다. 종료 이벤트 없이 죽은 연결이 화면을 영구히 멈추던 문제를
  해소하며, 프로토콜 변경 없이 이전 데스크톱과도 호환됩니다.

## 회귀 방지

- primary 포트 소멸 후에도 mirror ack 유무와 무관하게 PTY가 일시정지되지
  않는 인터프리터 회귀 테스트와 흐름 창 해제 계약 테스트를 추가했습니다.
- 실제 브리지·PTY로 단절→재개 후 스트림 지속과 ESC 가시 응답을 검증하는
  데스크톱 E2E(`remote-resume-stall`)를 추가했습니다.
- 실제 Android 앱 강제종료 후 대량 출력 스트림이 재개 뒤에도 계속 흐르고
  ESC가 화면에 응답하는 것을 검증하는 에뮬레이터 시나리오를 추가했습니다.
- 브리지 재시작 후 신원 보존, 게이트 재설정, 침묵 소켓 감지 각각에 대해
  수정 전 실패를 확인한 단위 회귀 테스트를 추가했습니다.

## 검증 범위

- 버전 계약, 타입 검사, 린트, Rust·루트·모바일 단위 테스트, 일반
  `pnpm e2e`, Windows 패키징 검증을 릴리스 게이트로 수행합니다.
- 기능 핫픽스 정책에 따라 릴리스 성능 벤치마크와 30분 모바일 소크는 실행하지
  않으며, 새 exact-SHA 성능 비교 결과를 주장하지 않습니다. 이번 결함에
  특화된 대량 출력 재개 시나리오가 에뮬레이터 증거를 대신 제공합니다.

자세한 지원 범위와 잔여 위험은
[1.0.10 검증 정책](validation-policy-1.0.10.md)을 확인하세요.
