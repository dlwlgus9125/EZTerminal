# r2 연결 흐름 검토 기록

**검토 대기 후보.** 이 기록은 시안의 작성자 검증이며 사용자 디자인 확정·제품 구현·실제 AI 실행 검증을 뜻하지 않습니다.

## 직접 확인한 화면과 보완

r1 일반 대화의 입력·메시지·스킬·확장 관리를 유지하며, 기존 r6 프로젝트 탭에 맞춰 기획·디자인·작업·검토 화면과 연결했습니다. 별도 단계 메뉴를 추가하지 않았습니다.

- Windows: 대화 상단의 원래 화면으로 돌아가기, 현재 참조 버전, 역할, 오른쪽 읽기 전용 참조를 확인했습니다.
- Android: 같은 참조는 시트에서 읽습니다. 실행 승인 장면에서 요청 내용을 확보하도록 입력창을 접고 명시적으로 다시 펼칠 수 있게 했습니다.
- 변경안: 원본·제안을 비교한 뒤 적용하며, 원본 갱신과 미저장 편집은 적용 차단 사유로 표시합니다.
- 단계 인계: 디자인에는 앞서 반영한 요구사항, 작업·검토에는 준비할 때 확정한 요구사항·디자인 snapshot이 함께 표시됩니다.
- 실행과 검토: 담당 AI의 실제 역할·작업 위치·확정 설정을 표시하고 독립 검토 대화를 구분합니다. 긍정적인 검토 답변으로 통합하지 않습니다.

## 자동 검증

최종 결과는 [qa-report.json](qa-report.json)과 [journey-report.json](journey-report.json)이 소유합니다.

- 공통 시안: **106개**. 기존 기능 흐름 21개, 36장면 × 두 기기의 렌더·넘침 72개, axe 9개, 좁은 화면 3개, 실행 오류·외부 요청 1개.
- 연결 시안: **15개**. 문서·대화 초안 보존, 명시 적용, 버전 충돌, 미저장 변경 보호, 일반 대화 독립성, 확정 설정 보호, Windows·Android 전체 연결 흐름, 대표 6개 장면의 axe, 실행 오류·외부 요청.
- 전체 연결 검사는 디자인 대화가 요구사항 v4를, 작업이 요구사항 v4·디자인 v3를 참조하는지 확인합니다. 준비 시 AI 턴이 증가하지 않고, 명시적 시작 시에만 증가하며, 담당 대화 재진입은 같은 세션을 재사용하는지 검사합니다.

초기 연결 테스트에서 모달 뒤의 같은 이름 버튼을 선택한 locator와 axe의 브라우저 context 생성 방식이 실패했습니다. 대상 모달 안으로 locator를 좁히고 별도 browser context를 사용한 뒤 해당 검사를 재실행했습니다. 이를 제품 버그 수정으로 표시하지 않습니다.

## 검증하지 않은 범위

실제 provider/daemon 연결, 문서 영구 저장, 모델 비용, 실행·Git 통합, Android APK·물리 IME·시스템 Back, 150% UI scale·200% text zoom, 스크린리더 전체 사용 흐름은 검증하지 않았습니다. 성능 벤치마크와 제품 `pnpm e2e`는 수행하지 않았습니다. 이번 변경은 새 reference 폴더의 시안에 한정됩니다.
