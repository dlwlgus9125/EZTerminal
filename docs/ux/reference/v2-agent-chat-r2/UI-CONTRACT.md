# 단계 연결 대화 r2 보완 계약

상태: **검토 대기 후보**. r1의 일반 대화·확장 관리 계약에 문서·단계·실행과의 연결을 추가합니다. 승인된 r6 원본, 활성 루트 계약과 제품 소스를 변경하지 않습니다.

## 소유권

[DESIGN.md](../../../../DESIGN.md)는 시각 판단, [frontend-design.md](../../frontend-design.md)는 기존 탐색·플랫폼·상태 계약을 소유합니다. 정확한 값은 기존 theme/token source를 따릅니다. r1의 [입력·확장 관리 계약](../v2-agent-chat-r1/UI-CONTRACT.md)은 이 문서에서 명시적으로 보완하는 연결 부분 외에는 유지됩니다.

선택 방향은 **공통 대화 UI에 출처·역할·참조·복귀 정보를 결합**하는 것입니다. 기존 프로젝트 영역을 유지하고, 단계 전환 자체가 AI 호출·대화 초기화·실행 재시작을 일으키지 않습니다.

## 대화와 단계의 관계

대화 하나에 모든 역할을 강제로 합치지 않습니다. 같은 주제의 논의는 기존 대화를 재사용할 수 있고, 구현 attempt와 독립 검토는 실제 실행이 소유한 세션을 엽니다. 대화가 바뀔 때는 제목 옆 역할과 참조 문서·버전으로 전환을 설명합니다.

화면의 공통 문법은 transcript, 입력, 스킬·명령, 모델·추론·권한, 첨부, 질문·승인, 도구 결과, 대기열, 복구입니다. 모델·확장 기능은 해당 제공자와 실행 권한이 실제로 지원하는 것만 사용합니다. 실행에 확정된 설정은 대화의 설정 메뉴나 `/model` 같은 명령으로 조용히 변경하지 않습니다.

단계별 차이는 연결한 맥락과 결과를 반영하는 동작입니다.

| 단계 | 참조 | 명시적 반영 동작 | 다음 연결 |
| --- | --- | --- | --- |
| 기획 논의 | 선택한 요구사항·완료 조건·저장된 버전 | 구조화된 변경안 생성 → 비교 → 적용 | 연결된 화면과 디자인 대화 |
| 디자인 논의 | 선택한 화면·상태와 관련 요구사항 버전 | 화면 변경안 비교 → 적용 | 해당 화면의 구현 작업 |
| 구현 | 확정본의 문서·역할 설정·작업·attempt | 실행 준비 → 시작, 실제 요청의 허용/거절 | 생성된 정확한 결과와 검증 |
| 독립 검토 | 결과 revision·commit·검증, 확정본의 기획·디자인 | 독립 검토 시작, 근거 확인 후 통합 결정 | 같은 결과로 복귀 |
| 일반 대화 | 선택한 프로젝트·작업공간·사용자 참조 | 일반 메시지 전송 | 사용자가 연결한 문서나 작업 |

기획·디자인의 자유로운 논의와 **구조화된 변경안 생성**은 구분합니다. 현재 제품의 변경안 생성 경로가 가진 Claude 제한·도구 격리를 보존합니다. Codex 논의를 열었다고 제공자를 자동으로 바꾸거나 일반 대화의 스킬 권한을 변경안 생성기로 전달하지 않습니다. 상세 한계는 [INTEGRATION.md](INTEGRATION.md)를 따릅니다.

## 출처·참조·복귀

대화 상단에는 출발한 영역으로 돌아가기, 참조 대상과 버전, 담당 역할, 참조 보기를 둡니다. 디자인 대화에는 이전 단계에서 저장·반영한 요구사항도 함께 표시합니다. 실행·검토 대화에는 실행 준비 때 확정한 문서 snapshot을 표시합니다. 이후 원본이 편집되어도 실행의 기준을 바꾸지 않습니다.

Windows의 충분히 넓은 창은 대화 옆에 읽기 전용 참조를 병치합니다. 좁은 창과 Android는 **참조 보기**로 같은 내용을 열고 대화로 돌아옵니다. 모바일에서 승인 응답이 필요한 동안에는 입력창을 접어 요청 내용을 보여 주고, 사용자가 입력을 펼칠 수 있게 합니다. 접힘은 초안 삭제가 아닙니다.

원래 화면으로 돌아오면 선택한 문서·화면·작업·결과, 문서 편집과 읽던 위치를 복원합니다. 대화로 다시 들어오면 같은 세션·초안·참조 버전·메시지 위치를 복원합니다. 앱의 기존 영구 저장과 Back 계약을 제품 반영 때 연결하며, 시안은 페이지 내 메모리 보존만 검증합니다.

## 반영과 충돌

- 저장하지 않은 문서 편집은 원래 화면에 보관합니다. 대화가 저장된 버전을 참조한다는 사실을 표시합니다. 이를 사용자 모르게 저장하거나 전송하지 않습니다.
- 대화 답변은 문서 변경과 실행 성공의 권위가 아닙니다. 변경안은 before/after와 대상 버전을 확인하고 명시 적용합니다.
- 원본 버전이 바뀌거나 미저장 편집이 있으면 적용을 막고 원본 확인으로 안내합니다. 기존 편집과 제안은 보존합니다.
- 문서 반영은 실행을 시작하지 않습니다. 기준 확정·실행 준비·시작을 구분합니다. 준비 중에는 현재 문서와 역할 설정을 검토합니다.
- 담당 AI 대화 열기는 현재 attempt의 세션을 재사용합니다. 질문 응답과 작업 승인은 실제 요청에 귀속됩니다.
- 검토 답변이 긍정적이어도 결과는 자동 통합되지 않습니다. exact revision 근거·독립 검토와 기존 호스트 검증을 통과한 별도 통합 명령을 사용합니다.
- 단계 전환과 원격 재연결만으로 메시지를 보내지 않습니다. 원격 변경은 기존 호스트 권한 경계를 그대로 사용합니다.

## 참조 시안과 제품 경계

r2는 일반 대화 25개 장면을 유지하고 연결 흐름 11개를 추가합니다. `journey.js`는 시안 데이터와 조작만 담당하고, `prototype.js`의 대화·스킬·확장 UI를 같이 사용합니다. 제품에 이 HTML/CSS/JS를 통째로 복사하지 않습니다.

제품 대응은 `PlanningWorkspacePanel`, `PlanningExecutionPanel`, `PlanningResultDetails`의 기존 동작을 유지하면서 대화 진입 시 source/return 정보를 추가하고 공통 `StructuredAgentSession`에 표시하는 것입니다. 상세 소스 근거, 필요한 추가 연결, 검증 조건은 [INTEGRATION.md](INTEGRATION.md)에 분리했습니다.

고정 palette를 추가하지 않습니다. 기존 런타임 토큰과 r6 이미지 사이의 색상 차이는 r1에서 기록한 별도 확인 사항으로 유지합니다. 이 후보는 디자인 확정을 자동 부여하지 않습니다.
