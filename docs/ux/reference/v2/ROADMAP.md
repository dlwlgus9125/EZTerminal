# EZTerminal 2.0 제작 로드맵

이 문서는 이번 작업을 수행하기 위한 로드맵이다. 제품에 독립적인 로드맵 메뉴·간트차트·로드맵 저장 모델을 추가하지 않는다. 제품 작업 화면은 선행 작업·담당·검토 지점을 표시한다.

P1–P5는 기획 자료 제작, P6–P7은 사용자 검토·확정이다. 2026-10-13 사용자의 전체 진행 지시로 r6 설계를 승인하고 G1–G8 구현을 허가했다. [승인 기록](APPROVAL.md)은 개별 화면 클릭 검토나 구현 완료를 주장하지 않는다. 11개 운영 정책을 포함한 실제 단계별 완료 근거는 [구현 진행 기록](../../../ezterminal-v2-implementation.md)에 남긴다.

## 실행 운영

- 모든 G 단계에서 Windows와 Android의 관련 계약·기능을 함께 완성한다.
- 대표 담당 1개와 작업자 최대 3개. 검토자가 필요하면 작업자 슬롯을 교체한다.
- 공유 type·token 변경은 한 담당이 관리하며 다른 작업자는 합의된 인터페이스를 사용한다.
- 기존 미커밋 변경을 보존하고 구현 시작 시 기준 revision을 다시 확인한다.
- 단계마다 로컬 통합 브랜치에서 기능·검증 근거를 확인한다.
- 일정 날짜는 아직 약속하지 않는다. 작업량과 검토 시간을 확인한 뒤 의존성 순서를 유지하며 배정한다.

## 실행할 때의 인계와 완료 조건

기획 이후 사용자 흐름은 [단계별 예상 화면](index.html#delivery), 제작 작업의 구체 입력·출력·인터페이스·검증은 [W01–W09 상세 인계](HANDOFF.md#작업별-상세-인계-계약)를 따른다. G2의 Windows·Android는 병렬 가능하며 G3은 양쪽 shell 완료 후 시작한다. G4·G5는 G3 이후 병렬 가능하다. 모든 단계의 독립 검토와 통합 후 검사를 통과한 뒤 다음 단계로 넘긴다.

[출시 준비와 실패 복구 기준](DELIVERY-DESIGN.md)을 G8 완료 조건에 포함한다. 코드 작성 완료·검사 미실행·기기 부재를 완료로 취급하지 않는다.

## r4 정책 보완 이력과 r6 승인 기준

2026-10-13에 11개 정책을 확정했고, 이후 r6 전체 진행 지시로 P6/P7 기준을 승인했다. 승인 범위는 [8개 정책 흐름·18개 장면](index.html#policies), 갱신한 U03/U08, 전체 59개 화면·48단계의 일치 여부다. 제작 실행 순서 G1–G8과 W01–W09는 유지한다.

| 단계 | 이번에 포함한 완료 조건 |
| --- | --- |
| G1 / W01 | Task/Session/Turn·변경 계획·repair series·profile snapshot·백업·offline draft·component·environment lease 계약 |
| G2 / W02·W03 | 빠른 작업 카드의 명시적 시작, Android 오프라인 열람·초안·재연결 직접 전송 |
| G3 / W04 | 변경 영향·후속 의존 집합·새 기준·무관 작업 유지 |
| G4 / W05 | 공통 요소·화면별 예외·확정본 고정·자산/상태/반응형 roundtrip |
| G5 / W06 | 참여 역할만 점검, 전체 프로필 편집·AI 제안 승인, 추가 재시도 2회·시간 제한 없음, AI 장애 대기, 환경 격리 |
| G6 / W07 | 변경 계획 적용과 재검토, 재시도·새 revision 근거, 통합 실패 보존 |
| G7 / W08 | 인증 제외 전체 기록 백업·복원, 기록 직접 정리, 기존 도구 보존 |
| G8 / W09 | Windows·Android 백업 이동·앱 재시작·오프라인 초안·불명확 실행 대조·전체 회귀 실증 |

r6 승인 범위에서 멀티에이전트 구현을 배정한다. 이번 패키지 QA는 설계 참고자료의 동작 확인이며 위 제품 검사 통과를 뜻하지 않는다.
