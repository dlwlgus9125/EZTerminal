# 검토와 구현 시작 조건

## 현재 판정

**r6 전체 설계 승인 / P6·P7 게이트 종료 / G1–G8 구현 진행 허가.**

근거는 2026-10-13 사용자의 **“정리할내용 정리하고 나머지단계 모두 진행해줘”** 지시다.
[승인 기록](APPROVAL.md)과 [manifest](approvals/2026-10-13-r6-final.json)에 발화·범위·시각·파일 해시를 보존한다.
자동 QA를 사용자 승인으로 해석한 것이 아니며 모든 화면을 개별 클릭해 확인했다고 기록하지 않는다.
`review-log.json`은 전체 승인과 개별 화면 상태를 구분한다. G1–G8 완료는 실제 구현·검증 근거가 필요하다.

승인 범위에는 [ai-operating-01](AI-OPERATING-MODEL.md)의 역할별 프롬프트·모델·팀 운영과
[delivery-01](DELIVERY-DESIGN.md)의 검증·통합·출시 준비, W01–W09 인계, r6 CLI 채팅 스킨을 포함한다.
실제 동작은 [구현 진행 기록](../../../ezterminal-v2-implementation.md)에서 확인한다.

## r4 정책 확정 이력

11개 운영 정책은 2026-10-13 사용자 최종 확인을 받았다. 당시 정책 확정만으로 전체 승인으로
전환하지 않았고, 이후 별도의 r6 전체 진행 지시를 승인 근거로 기록했다. [정책별 예상도](index.html#policies)와
[동작 계약](POLICY-CONTRACTS.md)은 다시 인터뷰할 선택지가 아닌 구현 수용 기준이다.

## 승인 전 검토 절차와 향후 변경 검토

1. 제품 정의·기능 범위·기존 기능 대응표를 확인한다.
2. 8개 사용자 흐름과 [기획 이후 7단계](index.html#delivery)를 예상 화면·프로토타입으로 따라간다.
3. Windows 43개·Android 16개 화면의 상세 시안과 필요한 상태를 확인한다.
4. 기획·실행 경계, 스킨·터미널 구분, 모바일·원격, 실패·복구를 확인한다.
5. 화면별 의견을 기록하고 검토 JSON을 내보낸다.
6. 수정한 시안·명세·흐름의 일치를 다시 확인한다.
7. 전체 설계를 확정하고 해당 버전을 구현 기준으로 지정한다.

## 차단 조건

- 요구사항·기능·화면·수용 기준 연결 누락.
- 기존 기능이 사라지거나 새 진입점이 불명확함.
- 시안과 명세가 서로 다른 동작을 설명함.
- 핵심 화면·오류·취소·복구 상태가 빠짐.
- 기획 확정만으로 실행하거나, 자율 실행이 합의한 로컬 종점을 넘어감.
- 미해결 사용자 검토 의견 또는 결정되지 않은 핵심 동작.

## 검토 기록의 의미

개별 화면의 '확인함'은 해당 브라우저에 기록한 사용자 검토 표시다. 전체 승인과 구분한다. 기록을 불러와도 자동으로 구현을 시작하지 않는다. 실행 허가는 이 문서의 체크박스나 프로토타입 버튼이 아니라 사용자의 실제 설계 확정·구현 지시로 판단한다.

## 검증 범위

문서용 QA는 화면 참조·렌더링·스크롤·버튼 이동·스킨·상태 선택·기록 내보내기와 주요 시안의 접근성을 확인한다. 제품 e2e·성능·Android 기기 실증을 통과했다고 주장하지 않는다. 제품 구현 이후 일반 검증은 `pnpm e2e`이며 성능 측정은 별도 요청이 있을 때만 수행한다.
