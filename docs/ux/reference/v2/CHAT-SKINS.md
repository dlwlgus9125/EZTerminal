# 채팅 기반 CLI 스킨 상세 설계

> r6 · 사용자 요구 반영 · 검토용 상세 시안. 전체 설계 승인과 제품 구현은 아직 대기 중이다.

**[상태별 상세 시안과 체험](index.html#chat-skins)**에서 같은 대화의 말풍선·CLI 표현을 나란히 비교한다.

## 제품 정의

실제 기능과 데이터는 메시지 기반 채팅이다. 말풍선과 CLI는 같은 채팅을 그리는 두 스킨이다. CLI 스킨을 선택해도 provider, model, 권한, 실행 모드, session이나 turn을 바꾸지 않는다. 터미널 에뮬레이터의 출력이나 키 입력으로 채팅을 구현하지 않는다.

이전 r5의 출력 영역 안 프롬프트와 별도 CLI 시작 배너는 이 제안에서 교체한다. 입력은 두 스킨 모두 같은 하단 채팅 composer에 있고, 메시지 기록만 별도로 스크롤한다. CLI 스킨의 `›`는 AI 메시지 입력 표시다. 셸 입력은 기존 D28/M09에서 명시적으로 연다.

## 변하는 표현과 유지할 동작

| 항목 | 말풍선 | CLI | 공통 계약 |
| --- | --- | --- | --- |
| 메시지 | 사용자 말풍선, 읽기 폭 중심 | 좌측 정렬, `›`·`●` 역할 표식, 조밀한 간격 | 같은 message ID·작성자·내용·전송 상태 |
| 메시지 동작 | 메시지 아래 복사·답장·입력에 가져오기 | 같은 위치의 작은 텍스트 동작 | 보낸 기록을 덮어쓰지 않음; 가져오기는 초안만 변경 |
| 입력 | 여러 줄 입력 상자 | 테두리를 줄인 프롬프트형 입력 | 같은 초안·커서·선택·첨부·답장·IME·전송 경로 |
| 첨부 | 썸네일·파일명·종류 | 같은 내용의 간결한 미리보기 행 | 보기·제거·전송 상태 유지; 스킨 전환으로 업로드 재시작 없음 |
| 도구 결과 | 접을 수 있는 상세 영역 | 접을 수 있는 출력 행 | 같은 실행 ID·내용·오류·열림 상태 |
| 산출물 | 카드 | 파일명과 설명이 있는 행 | 같은 문서·화면·버전 열기 |
| 승인 | 이유와 대상, 허용·거절 버튼 | 같은 정보와 버튼을 가진 직선형 영역 | 기존 권한·승인 정책 유지, 스킨 변경으로 승인하지 않음 |
| 응답 중 | 부분 응답·중단·대기열 | 같은 상태를 작은 표식으로 표시 | 전송된 후속 메시지는 별도 대기 항목, 현재 turn에 몰래 삽입하지 않음 |
| AI 설정 | 입력 가까이 담당·모델 선택 | 같은 동작을 작은 상태줄로 표시 | 호스트가 지원하는 값만 제공, 변경 적용 범위 명시 |

확인된 텍스트만 표시하며 관측하지 않은 내부 추론·사용량·진행률을 만들어내지 않는다. 참조 원문과 전체 경로는 펼쳐 확인할 수 있다. Matrix 테마와 CRT 효과는 CLI 스킨과 별도 설정이다. 정확한 제안 시각 값은 [prototype.css](prototype.css)에만 둔다.

## 상태와 전환

1. 같은 대화에서 스킨 버튼을 누르면 표현만 바뀐다. 스킨은 기기별 보기 설정이다.
2. 초안·선택 범위·답장 대상·첨부·펼친 도구·열린 산출물·승인 대상·대기열을 보존한다. 읽던 메시지 ID를 기준으로 스크롤을 복원한다. 길이가 다른 표현 사이에서 문서 전체의 픽셀 위치만 복사하지 않는다.
3. 전송은 메시지와 첨부·답장 참조를 하나의 요청으로 묶는다. 성공 receipt를 받기 전에는 로컬 초안을 복구 가능하게 보존한다. 상태 불명확 시 중복 전송하지 않고 호스트 기록과 대조한다.
4. 응답 중 전송은 대기열에 보관하고 현재 응답을 중단하는 동작과 구분한다. 중단 후에는 부분 응답·대기 메시지를 보존하고 자동 재시작하지 않는다. provider 지원 여부에 따른 제어 가능 범위는 기존 운영 계약을 따른다.
5. 오류·오프라인에서도 같은 메시지 기록을 유지한다. Android 오프라인 초안과 명시적 재전송은 [확정 정책](POLICY-CONTRACTS.md)을 따른다.

## 반응형·입력·접근성

Desktop은 대화 영역을 사용하고 산출물을 열면 나란히 배치한다. 좁은 폭에서는 산출물 페이지와 대화를 전환하되 입력과 읽던 위치를 유지한다. Android는 한 열로 표시하고 첨부·승인·결과를 터치로 열 수 있다. 메시지 목록과 입력부의 스크롤을 분리해 긴 로그가 입력을 밀어내지 않도록 한다. 첨부가 많거나 키보드가 열린 경우 첨부 행을 접어 입력과 전송을 보장한다.

Desktop Enter는 전송, Shift+Enter는 줄바꿈이며 IME 조합 중 Enter는 전송하지 않는다. Android Enter는 줄바꿈, 버튼은 전송이다. 선택한 텍스트의 복사와 실제 터미널의 Ctrl+C 의미는 기존 계약을 따른다. `›` 표시는 보조 기술에서 장식으로 처리하고 메시지 작성자·역할을 별도로 읽는다. 메시지 동작은 hover 없이도 키보드 focus와 터치로 접근한다. 상태는 색과 함께 텍스트로 표시한다. 실제 제품은 플랫폼 touch target·축소 동작·대비 규칙을 준수한다.

## 구현 인계와 검증 범위

W01은 메시지·첨부·승인·대기열의 단일 상태 계약, W02/W03은 Windows/Android의 두 스킨 표현·입력·보기 보존, W06은 실제 agent 이벤트·지원 제어와 연결한다. 새로운 CLI 실행 엔진이나 대화 저장소를 만들지 않는다. provider 연결·인증·상위 권한은 기존 설계를 유지한다.

검토용 HTML은 예시 상태만 전환한다. 이미지 파일 업로드, 실제 AI 스트리밍, 호스트 저장, 셸·외부 내보내기는 수행하지 않는다. 복사는 선택 가능한 원문 dialog로 시연한다. 파일 I/O·Android 키보드·앱 재시작·접근성 보조 기술과 실제 실행 수명은 제품 구현 단계의 검증 항목이다.

`node docs/ux/reference/v2/verify.mjs`는 같은 메시지 ID·내용, 초안 선택·첨부·답장, 승인·대기열의 스킨 전환 보존과 예시 전송을 검증한다. 상세 캡처·wireframe·작은 화면·대표 테마의 검증 결과는 [qa-report.json](qa-report.json), 작성자 시각 검토는 [VISUAL-REVIEW.md](VISUAL-REVIEW.md)를 따른다.
