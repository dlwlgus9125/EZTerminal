# 멀티에이전트 구현 인계

**현재 상태: r6 설계 승인 / G1–G8 및 W01–W09 구현 진행 허가.** [사용자 승인 기록](APPROVAL.md)을 기준으로 의존성 순서에 따라 구현한다. 개별 단계 완료는 실제 검증 근거가 필요하다.

모든 UI 작업의 design_context는 활성 [DESIGN.md](../../../../DESIGN.md)와 [UX 계약](../../frontend-design.md)이다. 이 폴더의 [DESIGN-PROPOSAL.md](DESIGN-PROPOSAL.md), [SCREENS.md](SCREENS.md), [CHAT-SKINS.md](CHAT-SKINS.md)는 승인 기준과 시각 근거를 제공한다. 정확한 값은 runtime token/theme가 소유하며 고정 desktop handoff는 변경하지 않는다.

- 산출물: Windows shell·한 칸 탐색·두 대화 스킨·실제 터미널 연결, 생산용 stories와 대응표
- 인터페이스·소유권: session ID·transcript 의미 유지. 스킨은 표현만 소유하고 실행·권한 상태는 호스트를 사용.
- 검증·통과 기준: IME 조합, 전송 대기 중 스킨 전환, draft·scroll·첨부 유지, 좁은 창 탐색·focus, 터미널 키. Storybook·시각·관련 e2e. 확정 정책: I02 빠른 작업 시작
- 실패 시: 표현 문제가 실행 수명을 바꾸면 완료 불가. W01 계약 변경이 필요하면 대표에게 인계.

### W03 상세

- 입력: W01 동일 명령 계약, M01/M02/M03/M04/M09/M16, 기존 Android 인증·Back·WebView 제약
- 산출물: Android 탐색·대화 스킨·원격 세션 제어·미확정 요청 복구, 실제 기기 검증 근거
- 인터페이스·소유권: PC가 데이터·실행 권위. 연결 유실 시 명령 상태 조회 후 같은 commandId 결과 대조, 임의 재전송 금지.
- 검증·통과 기준: IME·전송 버튼·Back·회전, 재연결·앱 강제종료, 동일 세션·PTY 입력 유지. mobile typecheck·test·WebView74·관련 기기 흐름. 확정 정책: I02 빠른 작업 시작, I07 Android 오프라인
- 실패 시: 기기 접근이 없으면 미실행으로 기록하고 Android 완료를 주장하지 않음.

### W04 상세

- 입력: W01 저장 계약과 W02/W03 shell, 승인한 기획·기능·IA·흐름·확정 화면, 기획 역할 프롬프트
- 산출물: 기획 CRUD·참조·AI 초안 편집·undo·baseline 생성·변경 영향, 두 플랫폼 편집·조회
- 인터페이스·소유권: 기획 도구는 허용된 namespace만 수정. expectedRevision·operationId를 가진 변경 묶음. W06 실행기는 공통 세션 adapter 경계로 연결.
- 검증·통과 기준: 동시 수동/AI/외부 편집 충돌, undo 대상 분리, 참조 삭제·만료, 확정본 분기, 코드 실행 도구 차단. 관련 통합·e2e. 확정 정책: I01 요구사항 변경
- 실패 시: 참조나 버전이 바뀌면 제안 재계산. 확정된 기준을 덮어쓰지 않음.

### W05 상세

- 입력: W04 참조·변경 계약, 확정한 scene 규칙과 D09–D12/M06 예상도
- 산출물: scene 저장·선택 요소 편집·상태별 체험·연결·이력, 접근 가능한 목록 대체 조작
- 인터페이스·소유권: stable elementId와 scene revision. 렌더러는 scene만 소비. AI 패치는 지정 요소와 허용 속성 범위로 검증.
- 검증·통과 기준: 선택 범위 이탈 차단, undo/redo, 끊어진 연결, keyboard·touch·좁은 화면. scene 단위·Storybook·시각·e2e. 확정 정책: I10 공통 UI 요소
- 실패 시: 잘못된 scene은 적용 전에 거절하고 원본 보존. 변경된 요소만 다시 요청.

### W06 상세

- 입력: W01 run/attempt·profile 계약, W04 Task 입력, AI 운영 설계와 D15/D16/D17/D19/D27/D36·모바일 대응
- 산출물: 역할 프로필·팀 프리셋·capability 검증·scheduler·attempt 기록·질문·후보 비교, 재시작 복구
- 인터페이스·소유권: D36 프로필 영역은 W06, 설치·인증 adapter는 기존 기능과 W08 소유. candidate selection은 W07 검토에 ID·revision만 전달.
- 검증·통과 기준: 팀 방식과 진행 정책 분리, 동시성 상한, unsupported 시작 차단, requested/effective, 늦은 완료·중복 질문·중지 실패·재시도, 자율 종점. 호스트 통합·e2e. 확정 정책: I01 요구사항 변경, I02 빠른 작업 시작, I03 검증 실패 재시도, I04 프로필 편집, I05 AI 프로필 수정 적용, I09 전체 실행 시간, I11 AI 연결·사용량 장애
- 실패 시: 기능을 지원하지 않으면 이유와 수정 경로를 표시. 불명확한 실행은 대조가 끝날 때까지 새 배정 보류.

### W07 상세

- 입력: W05 scene 비교·W06 후보/attempt, 정확한 revision 계약과 D20–D24/M08/M10
- 산출물: 설계·diff·실행 근거 비교, 검토 만료·수정 요청, 안전한 파일 저장, 로컬 통합 후보·복구 기록
- 인터페이스·소유권: 검토는 baselineId+artifactRevision+evidenceIds에 고정. 통합은 대상 base와 후보 revision을 다시 검증한 뒤 채택.
- 검증·통과 기준: stale review, 파일 외부 수정, 출처 없는 요소, 통합 충돌·부분 실패·기준 이동, 직전 성공점 복귀. 관련 호스트·e2e. 확정 정책: I01 요구사항 변경, I03 검증 실패 재시도
- 실패 시: 실패 후보를 격리하고 사용자 변경을 보존. 실패/미실행 검사를 green으로 표시하지 않음.

### W08 상세

- 입력: W07 통합 결과, 기존 기능 대응표와 외부 연결·보안·설정 계약
- 산출물: 기존 도구의 새 진입점, AI 설치·지원 기능 연결, export·외부 링크·진단, 대응표별 근거
- 인터페이스·소유권: 기존 서비스 수명과 credential 저장 재사용. 역할 프로필은 W06, 설치·인증·capability 공급은 W08. 외부 쓰기는 대상·변경 요약 확인.
- 검증·통과 기준: OpenClaw 실행/RPC 상태 분리, PC 입력 release, SSH 신뢰, 터미널·파일·자동화·tray·언어·theme 보존, 내보내기 roundtrip. 확정 정책: I06 전체 기록 백업, I08 기록 보관
- 실패 시: 연결/설치 실패를 실행 실패와 구분. 외부 결과가 미확정이면 조회·대조 후 처리.

### W09 상세

- 입력: W01–W08 통합 revision·전체 설계 대응표·단계별 검증 기록·깨끗한 테스트 설치 환경
- 산출물: 최종 기능·접근성·시각·이전 검증, Windows/Android 설치 파일·해시·동일 버전 증거, 알려진 문제·복구 안내
- 인터페이스·소유권: 각 단계의 독립 검토에 추가하는 최종 종합 검토. 패키지 source revision·version·검사 환경을 함께 고정.
- 검증·통과 기준: pnpm typecheck, pnpm test, pnpm e2e, 관련 Storybook/visual, 패키지 검증, Windows 설치·업데이트 및 Android 설치·force-stop·재연결. 성능 측정 제외. 확정 정책: I06 전체 기록 백업
- 실패 시: 필수 검사·플랫폼·이전 미검증이면 출시 준비 미완료. 원인 담당으로 인계하고 변경 범위와 전체 필수 회귀를 재검증.
