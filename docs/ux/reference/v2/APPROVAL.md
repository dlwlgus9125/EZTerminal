# EZTerminal 2.0 r6 설계 승인 기록

2026-10-13 사용자가 **“정리할내용 정리하고 나머지단계 모두 진행해줘”**라고 지시했다.
직전 대화의 설계 승인 전 점검과 r6 기준 정리를 포함한 전체 진행 요청을 근거로 P6 검토 게이트를
닫고 P7 설계 기준을 확정했다. G1–G8 및 W01–W09 구현·검증·패키지 준비를 진행한다.

- 기준: r6 전체 설계와 기존 확정 정책 I01–I11, Windows 43개·Android 16개 화면, 8개 사용자 흐름,
  기획 이후 단계, 같은 채팅의 말풍선/CLI 스킨, 기존 실제 터미널·운영 도구 보존.
- 영속 원본: [design-approval.mjs](design-approval.mjs).
- 승인 발화·범위·기록 시각·참조 파일 SHA-256: [승인 manifest](approvals/2026-10-13-r6-final.json).
- 활성 계약: [DESIGN.md](../../../../DESIGN.md), [frontend-design.md](../../frontend-design.md).
- 실행과 근거: [구현 진행 기록](../../../ezterminal-v2-implementation.md).

사용자 발화의 정확한 전송 시각은 제공되지 않아 승인일만 기록하고, 별도로 기록 생성 시각을
보존한다. 모든 화면을 개별 클릭해 검토했다는 증거는 만들지 않는다. 브라우저 화면별 검토·의견과
전체 설계 승인은 별개이며 기존 pending과 의견은 유지한다. 이 승인은 G1–G8 완료나 제품 QA 통과를
뜻하지 않는다. 성능 측정과 원격 main 반영·push·배포 자동 수행은 포함하지 않는다.

`build.mjs`는 승인 원본을 읽어 문서와 catalog를 재생성하며 `review-log.json`의 개별 화면 상태와
의견을 보존한다. 브라우저 기록 가져오기는 승인 원본을 변경할 수 없다. 승인 manifest는 생성한 뒤
덮어쓰지 않는 기록이다. 이후 파일 해시 차이는 새 변경으로 검토하고 기존 manifest를 갱신해 숨기지 않는다.

기존 r3·r4·r5의 검토 대기 문구는 해당 revision의 역사다. 현재 상태는 이 r6 승인 기록을 따른다.
시안 HTML은 계속 예시 상태만 표현하며 실제 AI·셸·내보내기를 실행하지 않는다.

후속 [상태 문구 정정 기록](approvals/2026-10-13-r6-status-correction.json)은 정책·인계·시각 검토 문서에 남은 r4 대기 문구 세 곳을 현재 승인과 구분한 편집이다. 이전 manifest는 그대로 보존하며 승인 범위를 바꾸지 않는다.

초기 manifest [2026-10-13-r6.json](approvals/2026-10-13-r6.json)은 기준 정리 중 생성한 기록으로 보존했다. 문서 계약 검사에 따라 진행 기록을 `docs/design/` 밖으로 옮기고 링크를 정리한 최종 manifest가 이를 계승한다. 승인 범위와 사용자 발화는 동일하다.
