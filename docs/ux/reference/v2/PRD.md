# EZTerminal 2.0 PRD

상태: r6 전체 설계 승인 · 구현 진행 허가. [승인 기록](APPROVAL.md). 실제 제품 완료·검증은 [진행 기록](../../../ezterminal-v2-implementation.md)에서 구분한다.

## 목적

한 사람이 AI와 대화하면서 아이디어를 검토 가능한 기획과 화면으로 만들고, 확정한 기준을 AI 작업과 결과 검증까지 이어간다. 대화·문서·디자인·실행 도구를 오가며 맥락을 다시 설명하는 부담을 줄인다.

## 사용자와 문제

주 사용자는 직접 기획·디자인·개발·검토를 조율하는 개인이다. 터미널에 익숙한 사용자와 대화형 작업을 선호하는 사용자를 같은 데이터와 제어 모델로 지원한다.

현재 겪는 문제는 (1) 대화 속 결정이 문서·화면에 반영되지 않는 것, (2) 검토 전에 코드가 먼저 바뀌는 것, (3) 여러 AI의 책임과 변경을 추적하기 어려운 것, (4) 실제 결과가 설계와 맞는지 확인하는 비용이다.

## 핵심 경험

아이디어 → PRD·기능 → 정보 구조·흐름 → 전체 화면 → 체험·검토 → 설계 확정 → 실행 준비 → AI 작업 → 근거 기반 검토 → 로컬 통합.

일반 대화, 빠른 작업, 실제 터미널은 바로 시작할 수 있다. 빠른 작업은 목표·대상·범위·완료 조건의 요약 카드를 확인하고 실행한다.

단계별 AI 프로필은 역할 지시문·참조·제공자·모델·도구·권한을 묶는다. 같은 AI를 여러 단계에 쓰거나 역할별로 다른 AI를 지정할 수 있다. 팀 운영은 단일·분업·후보 비교·독립 검토를 구분하며, 화면 이동만으로 AI를 시작하지 않는다. [AI 운영 설계 보강안](AI-OPERATING-MODEL.md)과 [역할별 프롬프트](AI-PROFILES.md)는 사용자 검토 대상이다.

## 제품 원칙

- 대화와 현재 산출물을 함께 본다. 선택한 항목·화면 요소·파일·변경은 대화의 명시적 참조가 된다.
- 말풍선·터미널형 스킨은 동일한 대화의 보기다. 실제 터미널은 별도 세션이다.
- 초안의 AI 수정은 즉시 반영하고 변경·되돌리기를 제공한다. 확정본은 변경 불가능하다.
- 확정은 실행과 다른 동작이다. 기획 단계의 도구 권한은 기획 원본 편집과 탐색에 한정한다.
- 대표 AI가 작업을 구성하지만 실제 상태 전이와 완료 판단은 호스트의 조건·검증을 따른다.
- PC가 실행과 저장을 소유한다. Android는 같은 작업을 보고 제어하는 클라이언트다.
- 현재 기능과 사용자 데이터를 보존한다. 신규 시작 기본값은 Dark·말풍선이며 기존 설정을 덮어쓰지 않는다.

## 확정 운영 정책

2026-10-13 사용자 확인을 마친 [11개 정책](POLICIES.md)을 적용한다. 해당 정책의 화면·담당·수용 기준을 추적하며, 세부 상태·데이터·복구는 [동작 계약](POLICY-CONTRACTS.md)이 소유한다. 전체 설계와 화면의 검토는 계속 진행한다.

## 성공 기준

1. 사용자가 같은 프로젝트에서 요구사항부터 실행 결과까지 연결을 따라갈 수 있다.
2. 모든 새 제품 화면에 정상·예외 동작과 수용 기준이 있고, 구현 전에 체험·검토할 수 있다.
3. 스킨·탐색·레이아웃 변경이 세션·입력·실행을 손상하지 않는다.
4. 여러 AI의 작업 범위·선행조건·담당·검증 결과를 확인하고 직접 개입할 수 있다.
5. 설계 변경과 코드 변경이 이전 검토의 유효성에 반영된다.
6. 기존 기능 대응표의 모든 기능이 새 구조에서 사용 가능하다.
7. Android의 재연결·중복 요청·뒤로 가기·터미널 상태가 보존된다.

## 범위 결정

Windows와 Android, 기획 편집, 전체 화면 설계, 프로토타입, 버전, AI 작업 관리, 편집·검토·미리보기, 기존 도구, 외부 연결과 내보내기를 포함한다. 별도 서비스 클라우드와 다중 사용자 실시간 편집은 현재 범위 밖이다. 이번 제작의 로드맵은 문서로 관리하며 독립적인 제품 기능으로 만들지 않는다.

실제 제공자의 capability·설치·인증은 확인된 범위만 표시한다. source map이 없는 실행 요소의 파일 위치, 제공되지 않는 비용·사용량, 검증하지 않은 성공률을 추정하여 표시하지 않는다.

## 완료와 출시의 구분

기획 자료 작성, 기계 검증, 사용자의 전체 검토, 설계 확정, 제품 구현, 출시 검증은 별도 단계다. 이 패키지를 만들었다는 사실만으로 설계 확정이나 제품 구현을 완료 처리하지 않는다.
