# EZTerminal 2.0 기획·설계 검토 패키지

**[검토 화면 열기 → index.html](index.html)**

`index.html`을 브라우저로 열면 설치·서버·로그인 없이 문서와 59개 화면을 검토할 수 있습니다. `화면 설계`에서 화면별 시안·와이어프레임·상태를 선택하고 `체험`으로 화면 이동을 확인하세요.

**[사용 흐름 + 예상 화면 보기](index.html#flows)**에서는 8개 흐름의 48단계와 8개 복구 장면을 함께 볼 수 있습니다. 위에서 흐름을 선택한 뒤 아래로 내려가면 각 단계의 사용자 행동·예상 화면·확인할 변화·다음 조건이 나란히 나옵니다. 상세 시안과 와이어프레임을 전환하거나 이미지를 눌러 크게 보고, 이전·다음 버튼과 방향키로 단계를 넘겨보세요. Escape로 닫으면 보던 단계로 돌아옵니다. 명세·검토와 화면 체험은 새 탭으로 열립니다.

**[기획 이후 단계 + 예상 화면 보기](index.html#delivery)**에서 실행 준비부터 검증·통합·출시 준비까지 7개 단계의 입력·담당 AI·산출물·통과 조건·실패 복귀를 확인할 수 있습니다.

**[확정 정책 + 예상 화면 보기](index.html#policies)**에서 이번에 확정한 11개 정책을 8개 흐름·18개 장면으로 확인하세요. 실행 전후·변경 영향·재시도 소진·AI 프로필 수정·대체 AI·전체 백업·오프라인 초안·공통 요소를 상세 시안과 와이어프레임으로 비교할 수 있습니다.

## 현재 상태

**r6 전체 설계 승인 · 구현 진행 허가.** 2026-10-13 사용자의 “정리할내용 정리하고 나머지단계 모두 진행해줘” 지시를 [승인 기록](APPROVAL.md)과 [파일 해시 manifest](approvals/2026-10-13-r6-final.json)에 보존합니다. [구현 진행 기록](../../../ezterminal-v2-implementation.md)은 G1–G8의 실제 완료 근거를 별도로 관리합니다.

- r6: **[채팅 기반 CLI 스킨 상세 시안](index.html#chat-skins)**. 같은 채팅의 말풍선·CLI 표현을 Windows/Android와 다섯 장면으로 비교합니다. 메시지 동작·첨부·답장·응답 중 입력·승인·결과 검토를 포함합니다. [상세 계약](CHAT-SKINS.md).

- r5 이력: 터미널형을 좌측 연속 출력·산출물 행·출력 뒤 프롬프트로 구성했던 시안입니다. r6에서 같은 채팅의 CLI 스킨과 하단 고정 입력으로 보완했습니다. [이전 시안과 검토 기록](VISUAL-REVIEW.md)을 보존했습니다.

- r4 이력: 11개 운영 정책 확정 완료. 19개 화면의 명세·진입·상태를 보완하고 빠른 작업 U03 및 변경 대응 U08을 갱신했습니다. 당시 전체 승인은 대기였으며 현재는 r6 승인 기록을 따릅니다.

- [AI 운영 설계](index.html#ai): 단계별 프롬프트·모델 설정과 단일/분업/후보 비교/독립 검토를 보강했습니다. 사용 흐름의 각 단계에서도 AI 역할을 펼쳐볼 수 있습니다. r4에서 프로필 직접 편집과 AI 수정 제안·버전 관리·장애 복구를 추가로 반영했습니다. 이 보강안을 포함한 r6 설계는 승인되었으며 실제 제품 검증은 구현 단계에서 수행합니다.

- r3 이력: 기획 이후 단계와 AI 설정을 12개 기존 화면에 반영했습니다. W01–W09 인계를 구체화하고 G3의 선행 조건을 양쪽 shell 완료와 일치시켰습니다. 변경된 화면만 다시 검토 대상으로 돌리고 기존 의견은 보존합니다.
- r2 이력: 프로젝트 영역은 상단, 세션·파일·검토 목록은 왼쪽 한 칸으로 정리했습니다. [탐색 개선과 전후 비교](NAVIGATION-REVIEW.md)를 확인하세요.
- 기획·설계 제안 자료입니다. 제품 구현이나 실제 실행 결과가 아닙니다.
- 전체 설계 승인과 브라우저의 개별 화면 검토는 구분합니다. 개별 클릭 기록을 임의로 완료 처리하지 않습니다.
- 승인된 시각·UX 계약은 활성 문서로 승격했습니다. 고정 handoff 원본은 유지하며 제품 변경은 구현 단계에서 검증합니다.
- 제작 로드맵은 이 작업의 실행 계획입니다. 제품의 독립 로드맵 기능은 제외했습니다.

## 검토 기록

브라우저의 의견과 화면별 검토 상태는 해당 브라우저의 로컬 저장소에만 저장합니다. `검토 기록 내보내기`로 JSON을 보관하거나 전달하세요. 다른 PC·브라우저에서 `기록 가져오기`로 다시 불러올 수 있습니다. 브라우저 저장이 차단되면 안내하고 메모리 상태 및 내보내기는 유지합니다.

화면의 체크는 사용자가 남긴 검토 표시입니다. 전체 기획 승인이나 구현 허가로 자동 해석하지 않습니다. 저장소의 `review-log.json`은 전체 승인 원본을 참조하며 개별 화면 상태와 의견을 별도로 보존합니다. 승인 발화와 해시는 [승인 기록](APPROVAL.md)이 소유합니다.

## 자료 원본과 재생성

- 기획 원본: `content.mjs`, `ai-planning.mjs`, `delivery-planning.mjs`, `policy-planning.mjs`. 여기서 `catalog.json`, `data.js`, 연결된 Markdown 문서를 생성합니다.
- 시각 값: `prototype.css`. 이 파일은 v2 **제안값**을 소유하며 현재 제품의 runtime token source를 대체하지 않습니다.
- 동작: `prototype.js`, `delivery-ui.js`, `profile-ui.js`, `policy-ui.js`. 모든 실행은 검토용 화면 시뮬레이션입니다. 네트워크 요청·셸·제공자 연결을 수행하지 않습니다.
- 이미지: `screens/detail/`, `screens/wireframe/`, `screens/policies/`. `verify.mjs`가 프로토타입에서 캡처합니다.
- 기계 검증: `qa-report.json`. 시각 검토 기록은 `VISUAL-REVIEW.md`와 구분합니다.

저장소 루트에서:

```powershell
node docs/ux/reference/v2/build.mjs
node docs/ux/reference/v2/verify.mjs
```

`build.mjs`는 승인 원본과 기존 화면별 상태·의견을 보존해 검토 기록을 재생성합니다. 개인 검토 기록은 브라우저에서 JSON으로 내보내 별도 보관하세요. 새 패키지 버전은 브라우저 검토 저장 공간도 분리합니다.

검증에는 프로젝트에 이미 설치된 Playwright·Chromium을 사용합니다. 제품 e2e 또는 성능 벤치마크를 실행하는 명령이 아닙니다.
