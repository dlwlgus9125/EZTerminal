# 일반 대화·확장 관리 r1 보완 계약

이 문서는 사용자 검토용 후보입니다. 확정 전에는 제품의 기존 계약을 대체하지 않습니다.

## 권한과 기준

- 시각적 정체성과 판단 기준: [DESIGN.md](../../../../DESIGN.md).
- 정보 구조·반응형·접근성·공통 상태 계약: [frontend-design.md](../../frontend-design.md).
- 정확한 색상·폰트·반경 등 런타임 값: [ui-tokens.css](../../../../src/renderer/styles/ui-tokens.css), [themes.ts](../../../../src/renderer/themes.ts). 이 시안의 `tokens.css`는 해시를 기록한 생성 사본입니다.
- 기존 승인 기준: [v2 r6 승인](../v2/APPROVAL.md), [기존 화면 목록](../v2/SCREENS.md), [대화 스킨](../v2/CHAT-SKINS.md).
- 제품 인계: [2.0 구현 기록](../../../ezterminal-v2-implementation.md).

기존 프로젝트·작업공간·대화 탐색 구조, Dark/Light/High Contrast/Matrix, 말풍선/CLI 스킨을 이어갑니다. 새 시안 때문에 루트 문서의 소유권이나 프로필을 변경하지 않습니다. 원본 handoff와 r6 snapshot을 수정하지 않습니다.

## 해결할 경험

일반 Codex·Claude 대화를 열면 첫 메시지를 보내기 전에 사용 가능한 스킬·명령, 모델·추론 옵션, 권한, MCP 준비 상태를 확인하고 선택할 수 있어야 합니다. 기능 탐색을 위해 가짜 메시지나 숨은 모델 턴을 만들지 않습니다. 설치된 확장을 찾고, 추가·수정한 뒤 작성 중인 대화로 돌아오는 흐름까지 포함합니다.

Codex·Claude 이름은 PC에서 실행되는 제공자 연동을 뜻합니다. 소비자용 데스크톱 앱 내부의 모든 기능을 동일 API로 사용할 수 있다는 약속은 아닙니다. 실제 지원 차이는 [SUPPORT.md](SUPPORT.md)에 따라 확인하고 화면에 이유와 다음 동작을 제공합니다.

## 정보 구조와 화면 구성

**Windows:** 기존 rail·project sidebar와 중앙 대화 영역을 유지합니다. 첫 화면의 준비 상태·스킬 바로가기에서 검색으로 진입하고, 입력 하단에 모델·추론·권한을 묶습니다. 명령·스킬 검색은 작성 위치와 가까운 선택 창입니다. 확장 관리 화면에는 실행 PC·제공자·범위 선택이 먼저 나타나고 스킬/플러그인/MCP를 나눕니다.

**Android:** 같은 정보 우선순위를 한 열로 표시합니다. 목록은 시트에서 선택하고 작성 영역은 대화 하단에 유지합니다. 상단과 관리 화면에서 실행 PC를 식별할 수 있습니다. 원격 PC 폴더와 휴대전화 첨부를 구분합니다. 원격 인증이 불가능한 단계는 PC에서 할 일과 돌아온 뒤 확인할 동작을 함께 제공합니다.

**검토 도구:** 상단 r1 도구 막대·장면 선택·검토 의견·예시 데이터 표시는 제품 UI 밖의 시안 기능입니다. 제품에 이 도구 막대를 이식하지 않습니다. 단색 면, 기존 semantic token, 현재 Lucide 아이콘으로 구성하며 새 브랜드나 별도 그래픽 자산을 도입하지 않습니다.

## 입력과 대화의 보존 단위

대화별 초안·커서·선택 스킬·파일 참조·답장 문맥·모델·추론·권한·스크롤·도구 펼침 상태를 소유합니다. 스킨 전환, 설정 방문과 복귀, 다른 대화 선택은 이 상태를 보존합니다. 새 대화는 빈 초안으로 시작합니다.

`/`는 명령과 스킬을 설명·출처와 함께 찾는 UI입니다. Codex 스킬 호출 표기는 `$`, Claude는 `/`로 구분하며 실제 전송 직렬화는 제공자 지원 확인 뒤 구현합니다. 선택은 칩을 추가하며 전송하지 않습니다. 검색을 여는 문자는 커서 위치에서만 치환하고 주변 본문을 보존합니다. `@`는 현재 실행 PC의 프로젝트 파일 참조를 찾습니다.

첫 전송에는 선택 스킬·첨부·답장 문맥을 포함합니다. 응답 중 작성한 메시지는 명시적 전송 시 대기열에 들어갑니다. 대기열 편집은 본문뿐 아니라 스킬·첨부도 복원합니다. 중단 후 전송과 일반 대기는 구분합니다. 대기 중 스킬을 삭제·비활성화했을 때 실제 전송 직전에도 유효성을 다시 확인해야 합니다.

Windows Enter/Shift+Enter와 Android의 전송 버튼 역할을 구분합니다. IME 조합 확정 Enter를 전송으로 처리하지 않습니다. 시안의 합성 이벤트 검증은 실제 Android IME 검증을 대체하지 않습니다.

## 기능 탐색과 관리

메타데이터는 실행 PC·제공자·프로젝트·설정 리비전에 귀속됩니다. 로딩/빈 목록/조회 실패/미지원/최신 목록/캐시 목록은 다른 상태입니다. 실제 제품에서 캐시를 보여줄 때는 마지막 확인 정보와 새로고침을 제공해야 합니다. 새로고침은 모델 턴이 아닙니다.

스킬은 이름·설명·출처·호출 표기·범위를 보여줍니다. 플러그인에 포함된 스킬은 소유 플러그인에서 설치·삭제를 관리합니다. 개별 스킬은 제공자가 지원하는 범위에서 사용 설정과 제거를 제공합니다. 선택한 스킬이 사용할 수 없게 되면 칩을 조용히 버리지 않고 전송을 막고 복구 경로를 표시합니다.

설치 출처는 기존 제공자 마켓, Git 주소, 연결된 PC의 절대 폴더 경로입니다. 설치 전 출처·포함 기능·PC·제공자·범위를 검토합니다. 대상이나 범위의 미지원 조합은 진행 전에 설명합니다. 업데이트·사용 설정·삭제는 기존 Codex/Claude 환경과 공유되는 설정을 대상으로 합니다. EZTerminal만의 별도 마켓 서버를 만들지 않습니다.

설치 성공과 현재 세션 적용 완료는 별개입니다. 런타임 재조회로 적용 가능하면 목록을 갱신하고, 새 세션이 필요하면 기존 대화를 유지한 채 적용 시점을 표시합니다. 다른 앱이 설정을 바꿨다면 최신 리비전과 대조하고 재검토하며, 작성 중인 값을 자동으로 덮어쓰거나 무조건 적용하지 않습니다.

MCP는 서버별 연결·인증·실패·사용 안 함 상태와 적용 범위를 제공합니다. HTTP 주소와 stdio 프로그램/인자를 구분합니다. 인증값을 일반 목록이나 대화에 노출하지 않습니다. Android 변경은 연결된 PC의 같은 권한 경계를 통과해야 합니다. UI의 버튼 노출만으로 원격 수정 권한을 부여하지 않습니다.

각 장면은 두 기기에서 직접 열 수 있으며 [catalog.js](catalog.js)가 실행 가능한 장면 목록입니다.

| welcome | 첫 턴 이전 | 스킬·모델·권한·MCP 확인, 첫 입력 |

## 접근성·국제화·검증 경계

기존 접근성 계약을 따르며 아이콘 버튼 이름, 키보드 포커스, 시트 focus trap과 닫은 뒤 복귀, 상태·오류 텍스트, 동작 감소 설정을 제공합니다. 파괴적 확인 창은 취소에 처음 포커스를 둡니다. 긴 이름·영문·CLI 스킨과 좁은 화면에서 작성 영역과 전송 동작이 사라지지 않아야 합니다. 한국어·영어 문구를 함께 검토합니다.

현재 시안은 브라우저 내부 상태 전환과 디자인 계약의 검토 도구입니다. 실제 연결·토큰 비용·실제 계정 메타데이터·APK 터치·소프트 키보드·스크린리더 완전성은 검증하지 않았습니다. 제품 반영 단계의 인수 조건에는 실제 Codex/Claude 각각의 0턴 탐색, native 설정 재조회, Android IME/연결 복구, 기존 대화 영구 보존을 추가합니다.

## 확정 후 제품에 연결할 위치

| 경계 | 현재 소스 | 확정 후 책임 |
| --- | --- | --- |
| 공통 대화 | StructuredAgentSession, StructuredAgentDockPanel, MobileStructuredAgentSession | 첫 화면·입력·진행·복구 상태를 공통 계약으로 구현 |
| 설정 | StructuredProviderSettings, AgentIntegrationSettings stories | 제공자·호스트·범위가 있는 확장 관리 |
| 제공자 | agent-provider-adapter, codex-provider-adapter, claude-provider-adapter | 턴과 독립된 capabilities 조회, 지원 차이 명시 |
| 실행 호스트 | daemon-agent-runtime, remote bridge | 캐시 격리·설정 리비전·권한·연결 복구 |

이는 구현 위치에 대한 제안이며 이 패키지가 해당 소스를 수정하지 않습니다. 기존 기획 실행의 격리 설정과 일반 대화의 사용자 확장 로딩을 분리하고, 현재 adapter에서 필요한 최소한의 capability seam을 확정 후 설계합니다.
