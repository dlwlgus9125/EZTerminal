# r4 소프로젝트·일반 대화·실행 그래프 UX 후보

상태: 사용자 요청을 반영한 검토 후보. 활성 제품 계약이나 디자인 승인 기록을 대체하지 않습니다.

시각 기준은 [DESIGN.md](../../../../DESIGN.md), 활성 흐름·입력·접근성 기준은
[frontend-design.md](../../frontend-design.md), 전체 후보는 [개선 계획](../../agent-workflow-plan.md)입니다.
기존 theme/token과 Lucide를 사용합니다. DESIGN 프로필 이전·새 브랜드·색상값 복사는 하지 않습니다.
적용 대상은 `src/renderer/`와 `mobile/src/`이며, 이 HTML/CSS를 제품으로 복사하지 않습니다.

## 정보 구조와 핵심 동작

- 프로젝트의 직접 자식은 소프로젝트와 일반 대화입니다. 하나의 목록과 동등한 생성 진입을 사용합니다.
  소프로젝트는 기존 기획 단위를 확장한 것이며 별도 ‘기획’ 부모를 만들지 않습니다.
- 소프로젝트는 목표와 흐름을 소유하고, 각 단계는 문서·산출물과 여러 공통 채팅 세션을 연결합니다.
  단계 이름이나 화면 배치를 바꿔도 nodeId와 session/message ID는 유지합니다.
- 생성 시 프리셋/대화 방식을 선택합니다. 생성 전에는 임시 초안만 있고 취소는 새 항목을 남기지 않습니다.
  생성·선택·노드 열기·스킬 탐색은 모델 턴이 아닙니다. 대화 전송은 별도 명시 동작입니다.
- 생성 뒤에도 노드·연결·담당 AI·지시를 편집합니다. 그래프와 목록은 같은 데이터를 사용합니다.
  실행 순서는 연결이 소유하고 화면 좌표와 구분합니다. 임의 단계 이름을 지원합니다.
- ‘흐름 편집’ AI 대화는 초안에 직접 반영합니다. 전후 변경·변경자·대화 출처와 되돌리기를 제공합니다.
  문서 제안·파일 변경·실행 시작·노드 승인까지 자동 허용하는 정책이 아닙니다.
- 일반 대화 연결은 같은 세션의 관계 변경입니다. 메시지/입력을 복제하거나 기존 문서를 덮어쓰지 않습니다.
  이미 실행에 연결된 대화의 소속은 재지정하지 않습니다. 프로젝트 집계 검색에서는 실제 소속을 표시합니다.
- 단계 삭제는 활성 초안의 노드/연결 제거이며 과거 대화·문서·실행은 보관합니다. 기록에서 기존 세션을 엽니다.

## 실행과 상태

| 상태 | 표현과 다음 행동 |
| --- | --- |
| 프로젝트/검색 결과 비어 있음 | 데이터 없는 상태와 필터 결과 없음 구분, 새 소프로젝트/새 대화 제공 |
| 생성 초안 | 이름·목표·프리셋/대화·흐름 미리보기, 취소 무생성 |
| 연결 정상 | 편집 가능, 별도 실행 준비 |
| 연결 오류 | 오류 원인·위치 표시, 초안 보존, 실행 시작 차단 |
| 실행 준비 | 버전·작업 위치·노드 AI 설정·참조·승인 단계 확인 후 명시 시작 |
| 실행 중 + 새 초안 | 실행 버전과 편집 초안 탭, 초안 수정이 현재 실행을 바꾸지 않음을 표시 |
| 분기·병렬/합류 | 조건 결과·활성 노드·기다리는 입력을 표시. 모든 결과 합류 조건을 지킴 |
| 승인 대기 | 해당 run/node/attempt와 승인 내용, 허용/거절을 실제 권한에 연결 |
| 일시정지·실패·한도 도달 | 원래 버전으로 재개 또는 초안 수정 후 새 실행. 무한 자동 재시도 금지 |
| 보관된 소프로젝트/단계 | 기록 열람, 복원 또는 남은 소속으로 복귀. 대화/결과 삭제 없음 |
| offline/loading/denied/unsupported/stale | 기존 상태 문법과 초안 복구, 실제 capability 재조회. 성공 모형으로 대체하지 않음 |

모형에서 구현한 상태와 실제 host 검증이 필요한 상태는 [검토 기록](VISUAL-REVIEW.md)에 구분합니다.
현재 실행은 시작 당시 graph/settings/references를 사용합니다. 그래프의 완료 노드는 자동 통합·배포가 아닙니다.

## 입력·반응형·접근성

Desktop은 기존 sidebar와 본문을 유지하며 그래프 옆에 단계 편집기를 둡니다. 좁은 창에서는 편집기를
아래로 옮깁니다. Android는 한 열 단계 목록이 기본이고 그래프는 별도 보기입니다. 노드/연결 폼을 통해
키보드·터치로도 편집하며 drag를 유일한 경로로 두지 않습니다. 캔버스의 내부 스크롤은 문서 가로 넘침과 구분합니다.

선택·실행·오류는 색 외에 텍스트와 테두리/아이콘으로 구분합니다. 버튼 이름, labelled input/select,
dialog 초기 focus·Tab containment·Escape·복귀 focus, reduced motion, 한영·기존 테마·말풍선/CLI를 유지합니다.
같은 세션의 입력·선택·스크롤은 화면 전환 중 보존합니다. 실제 Android Back/IME/safe-area·200% text zoom은
제품 구현에서 기존 계약대로 검증합니다. r4 HTML의 viewport 검사를 실기기 검증으로 확대하지 않습니다.

## 컴포넌트 경계와 시각 근거

공통 Button/Field/Select/Dialog/Badge 및 StructuredAgentSession, PlanningExecutionPanel/ResultDetails를
재사용합니다. 새 composition은 ProjectItemList, SubprojectCreate, WorkflowEditor/NodeInspector,
WorkflowValidation, StageConversations, WorkflowRunView입니다. 전역 token이나 provider 실행 소유권을
composition이 가져오지 않습니다. managed Agent 부모/자식 관계는 기존 채팅 track을 유지하고,
이 그래프는 사용자가 작성하는 작업 흐름만 표현합니다.

검토 oracle은 r3의 공통 채팅/문서 연결, r6의 승인 의도, 실제 production story와 이 후보의 행동 검사입니다.
고정 desktop handoff와 승인 snapshot은 수정하지 않습니다. r4 캡처는 새로운 후보 증거로만 보관합니다.
