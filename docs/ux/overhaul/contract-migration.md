# ux2 UX 계약 이관 기록

2026-10-23 [`frontend-design.md`](../frontend-design.md)를 다시 쓸 때, 개편 전 원문
([`reviews/2026-10-23-ux2-baseline/frontend-design.md`](../reviews/2026-10-23-ux2-baseline/frontend-design.md))의 기능 영역 규칙을
2부(§10–§27)로 옮긴 기록이다. 옮기면서 배치(어느 레일·사이드바·탭에서 여는지)를 말하던 문장은 규칙에서 빼고
아래 목록에 남겼으며, 1부 목표 IA가 이 목록을 다시 결정한다. 아래 "A<n>"은 이관 초안의 영역 번호이며 새 계약의 §(n+9)이다.

## 검수

- 이관 초안: Claude 에이전트(규칙 600여 개 + 상태 표 1개).
- 규칙 보존 검사: Codex gpt-6-astra(xhigh)가 원문과 대조해 누락 5건, 의미 변경 5건, 원문에 없던 규칙 2건을 찾았다.
  누락과 의미 변경은 모두 원문 의미로 고쳤고, 원문에 없던 2건은 이 기록(배치 목록·대조표)에만 있던 메모라 계약 본문에 넣지 않았다.
- 판단이 필요했던 항목: Android 결과는 1부 §7의 전체 화면 결과 페이지로 정함(원문 §16.3 "결과 페이지"와 R7.1 "시트"의 충돌),
  입력창 Shift+Tab 우선순위는 실제 구현(`StructuredAgentSession.tsx` keyDown) 순서대로 명시(§23),
  handoff 14개 표면 규칙은 2.0 reference manifest의 `legacy` 목록 기준으로 바꿈(§17).

## 규칙 대조표

셈 기준: 규범 문장 안에서 독립된 의무·금지·상태·검증 하나를 규칙 1건으로 센다. 이유 설명, `검토한 방향 1/2/3`
비교, 승인 경위, "미해결 제품 결정은 없다" 같은 서술은 규칙으로 세지 않는다. `찾은 규칙 = 이관 + 배치만`이다.
`이관`은 규칙 bullet(다른 절 bullet에 합쳐진 것 포함)이고, `배치만`은 규칙 부분 없이 배치 목록으로만 간 문장이다.
`분리`는 한 문장을 규칙(이관에 포함)과 배치 진술(목록에 포함)로 나눈 수다.

### 맡은 범위 밖이지만 규칙이 있는 절

리드가 새 IA 절을 쓸 때 놓치지 않도록 적는다. 이 파일에는 흡수하지 않았다.

- §10 도입부: Agent 원문 표시·보관(민감 표시로 숨기지 않음), 앱 대화의 primary/additional root(2026-10-22),
  `찾을 수 없음 · 이 대화에서 빠짐`, provider 색 hex와 3px start rail, CLI 탐색과 앱 대화 준비 분리.
- §10.1: 프로젝트별 Session history 하위 화면의 loading·empty·error·retry·pagination 상태와 검증 항목.
- §13.1–§13.3: same open command와 같은 path tab 재사용, preview·double-click pinning·Keep Open 없음, 등록 프로젝트
  밖 generic preview 경계.
- §16.1: 신규 기본값 Dark·말풍선, 기존 사용자 설정을 덮어쓰지 않음, 독립 로드맵 메뉴·간트차트·저장 도메인 금지,
  빠른 작업 시작 카드.
- §16.4: 시안 데이터·가짜 AI 응답·자동 캡처를 실제 provider/PTY/Android 검증으로 인정하지 않음, 시안 HTML/CSS 통째
  복사 금지.
