| # | 정한 것 | 이유 | 답 |

### 검수 기록

- 어드바이저: 관문 ① 산출물 점검. A/B는 크롬이 같고 다른 점을 분명히 할 것, 이어가기 비교에 워크트리 없는
  경우를 넣을 것, Android 비교 조건 표시, 골격 문구를 production 파일에서 뺄 것, 결정 목록을 답할 수 있게 쓸 것.
- Codex gpt-6-astra max: 판정 "수정 후 진행", 13건. 반영: 격리(흐름 실행 기록 제거, 관측 실패를 실패로),
  여정 종료 지점 통일, 승인 화면 가드 강화와 1.0 화면 은퇴, 1부·2부 충돌 해소(대체 예정 표시, 파일 탭 편집 제거),
  미흡수 규칙 복원, 결정 질문 보완(D①-7·9·10·11), 비교 조건 통제, 실제 SidebarShell 사용, 검토 도구 실패 검출,
  fixture 시각 합성화, CSS 토큰. 관문 ②로 넘긴 것: Android 한 줄 헤더의 ⋯ 메뉴에 작업 위치·확장·heartbeat 연결,
  탭 줄 키보드 이동(Dockview 탭 헤더로 대체).
- 2차 확인(어드바이저 + Codex gpt-6-astra max, 판정 "수정 후 진행"): 1차 13건 중 7건 해결·6건 부분 해결. 반영:
  여정이 끝 상태를 단언한 뒤에만 완료(새 대화는 가짜 호스트가 생성·전송을 받아 대화가 열림, 승인은 응답됨 상태,
  결과는 파일 변경 표시, 캔버스는 production React Flow 캔버스에 단계 표시, 단계 수가 다르면 실패), 승인 화면
  가드를 실행되는 `designReferenceCases` case와 축(두 언어 axe·screenshot·초점·viewport·넘침), 실제 날짜, 답이
  채워진 기록 행에 묶음, 검토 수집기가 모든 캡처에서 페이지 오류·크기를 검사, 수치 설명 정정(본문 증가를 띠 높이와
  띠 사이 여백으로 나눔, Android 초안 저장 상태 줄), D①-6 맥락별 제안표, S10 분리, D①-10·11에 달린 여정 값 표시.
  관문 ②로 넘긴 것(1차와 같음): ⋯ 메뉴 연결, 탭 키보드·tabpanel, 골격 a11y 검사 `todo` → `error`.
- 3차 확인(Codex gpt-6-astra max, 판정 "수정 후 진행", 필수 2묶음): 2차 기록의 보장이 덜 닫혀 있었다. 반영: 여정마다
  단계 수를 하나로 고정(B 이어가기 2단계는 목록에서 대상이 바로 보일 때만, A 워크트리 4단계는 로컬 묶음이 접혀 있을
  때만, 둘 다 단언), 결과 여정은 이름 있는 파일의 변경 화면이 보여야 완료, 승인 화면 가드는 건너뛴 테스트
  (`test.skip`·`describe.skip`·본문 안 skip)·다른 story·다른 screenshot·같은 언어 두 번·case와 무관한 다른 언어·
  viewport 밖 넘침 검사를 거부하고 승인 행은 id가 정확히 같은 칸만 인정. 검토 시트의 본문 증가 분해는 반올림 차를
  여백 쪽에 넣어 합이 맞게 했다.
- 4·5차 확인(Codex gpt-6-astra max, 범위: 앞 차수 필수 항목만): 여정 묶음은 4차에서 해결 확인. 승인 가드는 정적 검사를
  하나씩 막으면 다른 우회가 나와서 설계를 바꿨다: visual spec은 고정된 한 문장으로 case를 helper에 넘기기만 하고, 모든
  검증은 manifest `approvedChecker`가 SHA-256으로 고정한 helper 하나가 하며, 답은 표의 `답` 열에서 읽는다. 5차가 고정
  파일을 건드리지 않는 우회 둘(spec 안 같은 이름 helper, 반복 전 case 목록 비우기)을 재현해, helper는 고정 파일에서
  이름 그대로 import해 한 번만 쓰고 case 목록은 맨 위 const 하나를 반복문만 읽게 막았다(테스트 48개). **알려진 한계:**
  가드는 소스 모양을 보는 정적 검사라 모든 실행 경로를 증명하지 못한다. 고정 helper를 바꾸면 해시가 깨져 검토에 드러나고,
  실제 실행 증거는 CI의 `pnpm test:visual`이다. 이 기준으로 관문 ①의 가드 검수를 마친다(추가 차수 없음).
