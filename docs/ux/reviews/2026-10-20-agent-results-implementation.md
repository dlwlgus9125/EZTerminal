# 대화 결과물 탭 구현 기록

상태: 구현과 로컬 검수 완료. 공개 배포나 설치판 확인을 뜻하지 않는다.
계약: [frontend-design §16.6](../frontend-design.md#166-대화-결과물-탭--2026-10-20). 브랜치 `feat/agent-results`(기준 `ed9d33a`).

## 요청과 범위

사용자 요청(deep-interview로 확정): Claude Code 데스크톱, Codex, Paseo처럼 AI 대화 오른쪽에
작업 결과물 탭을 둔다. 탭은 세 구역으로 나뉜다.
- ① 변경 내역: 마지막 턴, 대화 전체, 작업 폴더(git) 범위. 줄 의견은 입력창 초안에 넣는다.
- ② 파일·산출물
- ③ 계획·작업

겹치는 기존 기능은 "보는 곳은 결과물 탭, 결정하는 곳은 입력창 위" 원칙으로 합친다.

범위에서 뺀 것:
- 브라우저(localhost) 미리보기
- git stage·revert·commit
- 결과물 편집
- 외부 CLI 기록 대화
- Android 변경
- 프로토콜·DB 버전 변경

## 구현

- **데이터**:
  - Claude 편집은 SDK `structuredPatch`의 실제 hunk로 기록하고, 새 파일은 내용 전체를 번호 붙은 추가로 기록한다.
  - Codex는 새 파일·삭제 파일을 번호 붙은 hunk로 기록한다. 예전 기록은 결과 payload의 파일 종류로 보정한다.
  - 기록 형식(`ezterminal.file-changes.v1`)은 그대로라 Android와 구 호스트가 읽을 수 있다.
- **화면**:
  - 결과물 탭은 Dockview `agent-results` 패널이다. 대화 탭이 같은 JS realm의 store에 publish한 내용만 읽는다.
  - `AgentResultsDock`이 배치, 활성 대화 따라가기, 대화와 함께 닫기, 사람이 닫은 경우의 기억을 맡는다.
  - 레이아웃 스키마는 owner id만 저장하고, owner 없는 탭은 정리한다.
- **통폐합(데스크톱)**:
  - 헤더 `결과물 N`, 턴 변경 요약과 파일 행, 메시지 속 파일 링크가 결과물 탭을 연다.
  - 대화 안 변경 검토 aside·대화상자와 턴 카드 인라인 diff는 없앴다.
  - 작업 도크는 진행 한 줄만 보이고 누르면 ③을 연다.
  - 결정 도크는 그대로다. Android 검토 시트도 그대로다.
- **격리 미리보기**:
  - main이 파일 하나(PDF) 또는 페이지 폴더 하나(HTML)에 대한 무작위 `ezartifact://<token>/` 권한을 준다. 30분 동안 쓰지 않으면 사라지고, 최대 32개이며, 닫으면 반납한다.
  - HTML은 스크립트 없는 sandbox에서 자기 권한의 CSS·이미지만 불러온다.
  - 앱 CSP는 이 미리보기만 frame으로 허용한다. 서브프레임 이동은 미리보기와 Chromium PDF 뷰어로만 허용한다.
  - PDF 뷰어를 위해 main·분리 창은 `plugins: true`다.

## 계획과 달라진 점

| 항목 | 계획 | 실제 | 이유 |
| --- | --- | --- | --- |
| HTML 미리보기 | 스크립트 실행, 네트워크 차단 | 스크립트 없음(정적), `브라우저로 열기` | iframe은 앱 세션을 공유하고 CSP `webrtc`는 미구현이다. 스크립트가 WebRTC로 내보내는 것을 막을 수 없다. 자동 열림과 첫 파일 자동 선택 때문에, 이대로면 명령 승인 없이 쓸 수 있는 송신 통로가 된다. 스크립트 실행 미리보기는 네트워크를 막은 별도 세션 뷰(브라우저 패널과 함께)로 미룬다. |
| Codex `turn/diff/updated` | — | 저장하지 않음 | 캡처상 항목별 diff를 합친 것과 같다. 저장하려면 구 Android에 낯선 행이 생긴다. |
| ③ 실행 중 항목 | 하위 AI·명령 | 전경 도구 호출과 하위 AI | Claude 백그라운드 Bash는 앱이 추적하지 않는다. |
| 분할 기준 | 960 px | 720 × UI 배율 | 실제 설정(Windows 125%, UI 130)에서 대화 옆이 아니라 숨은 탭으로 열렸다. |
| 자동 열림 | 이번 실행에 새로 온 결과물(sequence 기준) | 이 창에서 연 시각 이후(60초 여유) 생긴 결과물. 다시 막는 것은 사람이 닫았을 때뿐 | 새 대화의 첫 응답은 시작 화면에서 대화로 넘어가는 사이에 도착한다. 대화 탭을 닫는 것은 결과물을 닫는 것이 아니다. |
| 워크벤치 Storybook 시안 | dockview 합성 스토리 | 실제 Electron e2e 캡처 | 실제 앱 증거가 더 강하다. 좁은 창 배치는 실제 dockview 엔진 단위 테스트로 대체했다. |
| 헤더 버튼 | 결과물이 있을 때만 | 항상 `결과물`, 수가 있으면 `결과물 N` | 발견성 |
| 모바일 검토 시트 | `PatchLineList` 공유 | 기존 그대로 | Android 비변경 범위 |
| 메인에서 권한을 작업 폴더로 제한 | — | 하지 않음 | 메인은 `readFilePreview`와 같은 방식으로 렌더러를 신뢰한다. AI 데이터 경로는 렌더러에서 거르고, 숨김 이름은 거부한다. |

함께 고친 기존 결함:
- **시작 화면**: AI를 고르기 전에 계획·권한을 바꾸면 "Invalid chat draft" 오류가 나고, 이후 초안 저장도 실패했다. e2e는 낙관적 표시에 기대 통과하고 있었다.
- **작업 폴더 diff**: 따옴표로 감싼 경로(새 파일·공백 이름)를 직전 파일에 합치고 있었다.

## 한계(정직하게)

- **네트워크 차단은 최선 노력이다**: `<link rel=preconnect>` 같은 연결 힌트는 CSP 대상이 아니다.
- **격리 보장은 패키지 빌드 기준이다**: 개발 모드에는 렌더러 CSP가 없다.
- **권한 처리기가 없다**: 앱에는 원래 Electron 권한 처리기가 없다. 미리보기는 스크립트가 없어 권한을 요청할 수 없으므로 새로 노출되는 것은 없다.
- **PDF 다운로드**: 앱에 다운로드 처리기가 없어 Electron 기본 동작(저장 대화상자)을 따른다. 뷰어의 다운로드 버튼을 실제로 눌러 확인하지는 않았다.

## 검증

- **단위·스토리·visual**:
  - 단위 테스트와 guard 전체, 모바일 테스트, Storybook(결과물 탭 14).
  - visual: 결과물 탭 4개는 WCAG 2.1 AA를 포함한다. Light 선택 행 대비 4.11은 수정했다.
- **실제 Electron e2e** `e2e/agent-results.spec.ts`(가짜 Codex app-server) 4개:
  - 자동 열림, 포커스 유지, 줄 번호, 의견을 초안에 넣기(전송 없음)
  - 닫은 뒤 다시 저절로 열리지 않음, 대화와 함께 닫힘, 재시작 후 복원
  - 정적 HTML(스크립트 미실행, 같은 폴더 CSS), 밖으로 나가는 링크 차단과 복귀, PDF 뷰어
  - 새 창으로 옮긴 탭
- **실앱 확인**(격리 프로필, 사용자 테마 Matrix·CLI·CRT·UI 130):
  - 실제 Claude: 결과물 탭이 대화 오른쪽에 자동으로 열렸다. 활성 패널과 포커스가 유지됐다. 줄 번호 diff가 나왔고 부분 기록은 0이었다. HTML 정적 미리보기를 확인했다.
  - 실제 Codex: 같은 항목을 확인했다.
  - 렌더러 CPU는 최대 6~8%, 평균 3%였다.
- **증거 자료**: `artifacts/agent-results/{p2,p2-scale150,e2e}`(README 포함), `artifacts/ux-overhaul/p-results2-live-user`. 둘 다 저장소에 커밋되지 않는다.
